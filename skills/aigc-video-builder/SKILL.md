# Cinematic Prompt Builder（电影级视频提示词构建器）

本 skill 直接产出**成品、可复制粘贴**的 AI 视频生成提示词。交付物是 prompt 本身——一个用户能直接贴进视频模型的干净英文文本块——绝不是"这条 prompt 可以怎么写"的元描述。

**双份交付**：每条 prompt 交付时包含两部分——

1. **英文 prompt 成品块**（放在 fenced code block 里，保持英文，可一键复制直接投喂视频模型）；
2. **中文解释**（紧跟在代码块之后，逐段说明这条 prompt 的结构在做什么、关键词为什么这样写、哪些参数用户可以自行替换调整）。

## 这里的"好 prompt"标准

无论什么风格，本 skill 产出的每条 prompt 都必须遵守五条不可妥协的原则：

1. **第一帧就有运动（Motion from frame one）。** 不允许静态定场镜头干等。第一秒内摄影机和至少一个画面元素已经在动，动作立刻发生，不许"停一拍再开始"。
2. **三层景深（Three-layer depth）。** 前景、中景、背景全部填满内容。面对巨大主体时，用人物（或角色）作为比例参照物。
3. **引用锁定（Locked references）。** 当用户提供了引用素材（`@image_1`、`<<<video_1>>>`、Notion 产品链接、具名角色）时，prompt 必须声明与引用 100% 一致、点名保留了哪些具体元素；对于视频合成，还要声明源片不重新调色、不改变速、不重新构图。
4. **真实物理与实用光源（Real physics and practical light）。** 质量感、重力、惯性、接触阴影、表面张力，光照必须来自场景内的真实光源。不允许悬浮道具，不允许平光。
5. **从构建层面规避内容政策风险（Content-policy-safe by construction）。** 把场景从一开始就写成永远不需要描绘违规内容的样子。见 `references/content-policy.md`——只要场景涉及冲突、生物、人群、破坏、武器或未成年人，就必须加载该文件。

## 工作流程

1. **判断风格/格式。** 把用户请求匹配到下方的格式模板之一（或自行组合新格式）。如果确实在两种差异很大的格式之间难以判断，问一次即可；否则直接推断，并在交付时用一句话说明所做的假设。
2. **锁定时长与结构。** 决定：单个连续 **oner**（一镜到底，全程无剪切）还是 **multishot**（在指定时间点硬切）。默认跟随用户暗示的方向；大多数范例是 15 秒。
3. **写之前先加载相关参考文件：**
   - `references/structure.md` — 完整的段落词汇表、排列顺序、prompt 组装方法。**永远最先读这个。**
   - `references/styles.md` — 各风格配方（实拍电影感、3D 动画、游戏过场 + HUD、游戏实机、FPV oner、产品/商业广告、VFX 合成、怪兽/生物）。读匹配到的那一节。
   - `references/content-policy.md` — 安全构建规则与替换方案。只要场景有任何风险面就要读。
4. **按选定模板写 prompt。** 遵守下方的输出格式规范。
5. **直接交付**：先给英文 prompt 的干净 fenced block，再给中文解释；如有假设用一句话注明。不要用多余的客套话填充。

## 输出格式规范

以下是用户已确立的工作规范——除非用户明确要求覆盖，否则一律遵守：

- prompt 以 **STYLE 行 / 风格前缀** 开头（逗号分隔的风格描述词，或一句 `Style:` 开头的句子），然后是结构化段落，再是逐镜头拆解，最后是约束/音频。
- 使用 `references/structure.md` 中的段落词汇表。不是每条 prompt 都需要全部段落——只放场景实际用到的段落，按规范顺序排列。
- **镜头/段落拆解**在 multishot 格式下必须带明确时间码（如 `Shot 2 (0:05–0:10)` 或 `[Section 3 — 4.0–6.5s]`）。oner 则在一个连续段落内用节拍时间戳（如 `0:04–0:05 — the jolt`）。
- 明确标注剪切：段落之间写 `HARD CUT —`；oner 则声明 `one take no cuts`。
- **AUDIO** 段落放在接近结尾处。默认 `NO MUSIC. SFX ONLY — diegetic sound throughout.`（无配乐，仅环境内真实音效），除非用户想要配乐。
- 多元素 prompt 以 **CONSTRAINTS**（约束）和/或 **POSITIVE LOCKS**（正向锁定）块收尾，重申画幅比例、引用保真度，以及绝不能被打破的规则。
- 声明画幅比例（默认 **16:9**）和总时长。
- 行文保持密集、指令式。不要废话，不要"the viewer feels"这类观感描述，不要任何不影响渲染结果的营销形容词。
- **中文解释部分**：放在英文 prompt 代码块之后，按 prompt 的段落顺序逐段解释——每段在做什么、关键英文术语是什么意思、为什么这样写、用户想改内容时应该动哪里。解释要实用简洁，不要复述整条 prompt。
